# Командная доска маркетинга

Доска команды: месячный план с хабами и схемой задач, тестовая доска, идеи, созвоны с автоматической расшифровкой и брифом, доступы с подтверждением входа и журналом действий.

**Стек:** Next.js (хостинг Vercel) · Supabase (база, вход через Slack и почту, хранилище записей) · OpenAI (расшифровка речи) · Claude API (брифы).

---

## Запуск с нуля

### 1. База данных
1. Supabase → ваш проект → **SQL Editor** → **New query**.
2. Вставьте целиком файл `supabase/migrations/0001_init.sql` и нажмите **Run**.
   Он создаёт таблицы, права ролей, заявки на вход и приватное хранилище записей `recordings`.

### 2. Вход
- **Slack:** Authentication → Sign In / Providers → **Slack (OIDC)** включён, Client ID и Secret из Slack-приложения вставлены.
  В Slack-приложении в «OAuth & Permissions» указан Redirect URL `https://<project-ref>.supabase.co/auth/v1/callback`.
- **Почта:** провайдер Email включён по умолчанию. Встроенная отправка писем Supabase имеет низкий лимит в час. Для команды больше 3–4 человек подключите свой SMTP (Authentication → Emails → SMTP Settings), например Resend или почту компании.

### 3. Ключи
**Обязательные** (Supabase → Project Settings → API):
| Переменная | Что это |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ключ `anon` / publishable |
| `SUPABASE_SERVICE_ROLE_KEY` | ключ `service_role` / secret. **Никому не показывать** |

**Необязательные.** Без них доска работает полностью, но транскрипт созвона вставляется вручную, а бриф не собирается сам.
| Переменная | Что это |
|---|---|
| `TRANSCRIBE_API_URL`, `TRANSCRIBE_API_KEY`, `TRANSCRIBE_MODEL` | сервис расшифровки речи с OpenAI-совместимым API (`/audio/transcriptions`). По умолчанию OpenAI |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | брифы через Claude API |
| `LLM_API_URL`, `LLM_API_KEY`, `LLM_MODEL` | или брифы через любой сервис с OpenAI-совместимым `/chat/completions` |

### 4. Хостинг на Vercel
1. vercel.com → войти через GitHub → **Add New → Project** → выбрать этот репозиторий.
2. В **Environment Variables** добавить все ключи из таблицы выше.
3. **Deploy**. Через пару минут появится адрес вида `https://team-board-xxx.vercel.app`.

### 4б. Хостинг на Render (если Vercel недоступен)
1. render.com → войти через GitHub → **New → Blueprint** → выбрать этот репозиторий.
2. Render прочитает `render.yaml` и попросит три ключа Supabase. Вставьте их и нажмите **Apply**.
3. Первая сборка идёт 3–5 минут. Адрес сайта будет вида `https://team-board-xxxx.onrender.com`.
4. Дальше, как в шаге 5: этот адрес указывается в Supabase → URL Configuration.

На бесплатном тарифе Render сайт засыпает после 15 минут без посещений, и первое открытие после этого занимает около минуты. Тариф Starter ($7/мес) убирает засыпание.

### 4в. Свой сервер (VPS): без Vercel и Render
Нужен сервер с **Ubuntu 24.04**, 1–2 ГБ памяти, доступ по SSH под root. Подойдёт любой провайдер, где вы можете оплатить сервер.

1. Подключитесь к серверу: `ssh root@IP_СЕРВЕРА`.
2. Выполните:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/aklu65hdow/ss2team-board01/main/deploy/install.sh -o install.sh
   bash install.sh
   ```
   Если репозиторий приватный: `GITHUB_TOKEN=токен bash install.sh`, а скрипт скачайте через `git clone` с тем же токеном или скопируйте вручную.
3. Скрипт спросит три ключа Supabase и домен. Если своего домена нет, просто нажмите Enter: будет бесплатный адрес вида `1-2-3-4.sslip.io` с HTTPS.
4. В конце скрипт выведет адрес доски и что вписать в Supabase → URL Configuration.

Обновление до новой версии: `sudo bash /opt/team-board/deploy/update.sh`. Ошибки: `journalctl -u team-board -n 100`.

### 5. Связать адрес сайта с входом
Supabase → Authentication → **URL Configuration**:
- **Site URL:** адрес сайта с Vercel.
- **Redirect URLs:** добавить `https://<адрес-сайта>/auth/callback`.

### 6. Первый вход
**Войдите первым сами**: самый первый вошедший автоматически становится администратором. Все следующие попадают в «Доступы и логи → Заявки на вход», где вы одобряете человека и сразу назначаете роль, или отклоняете заявку.

---

## Роли
- **Администратор:** одобряет людей, создаёт хабы и задачи, правит всё, видит журнал.
- **Медиабайер:** двигает свои задачи и тесты, создаёт тесты, идеи, созвоны.
- **Наблюдатель:** только смотрит.

Права проверяются в базе данных (Row Level Security), а не только в интерфейсе.

## Созвоны
Загрузите запись (аудио или видео до 50 МБ). Сервер сжимает её до речевого качества, режет на куски по 10 минут, расшифровывает и затем собирает бриф через Claude. Статус виден на странице созвона. Стоимость: около $0.2–0.4 за час записи на расшифровку и несколько центов за бриф.

Ограничение по времени обработки задаётся `maxDuration = 300` секунд в `app/api/transcribe/route.js`. Если длинные записи обрываются по таймауту, проверьте лимит длительности функций на вашем тарифе Vercel.

### Бриф и расшифровка без ключей
Если ключи не заданы, на странице созвона есть «Собрать бриф вручную»: скопируйте запрос, вставьте его в любой чат-ассистент, а ответ вставьте обратно. Доска разложит его по полям брифа.

Подключить автоматический бриф и расшифровку на своём сервере: `sudo bash /opt/team-board/deploy/configure-ai.sh`. Скрипт спросит адрес API, ключ и модель любого OpenAI-совместимого сервиса и перезапустит доску.

## Как устроены данные
Доска хранит записи как JSON-документы в таблице `docs` по путям (`hubs/<id>`, `tasks/<id>`, `tests/<id>/comments/<id>`, `calls/<id>` и т. д.), так интерфейс перенесён из прототипа без переписывания. Профили, роли и журнал лежат в отдельных таблицах `profiles` и `logs`. Если позже понадобится аналитика по задачам или интеграции, документы можно разложить по отдельным таблицам.

## Локальная разработка
```bash
cp .env.example .env.local   # заполнить ключи
npm install
npm run dev                  # http://localhost:3000
```
Для локального входа добавьте `http://localhost:3000/auth/callback` в Redirect URLs в Supabase.
